Technical Audit of ChatGPT / GPT-5.6 Sol Reliability

Instruction-to-action binding, correction recovery, multimodal reference handling, and image-generation workflow incidents

Status: Public technical audit and evidence package. The main report is v1.3 (30 Aug 2026), extended by supplemental evidence covering 4–6 Sep 2026. This is a user-authored technical report, not an OpenAI publication and not a peer-reviewed paper.

Abstract

This project documents repeated reliability failures observed during a long-running ChatGPT / GPT-5.6 Sol multimodal workflow. The central question is not whether the model can understand explicit constraints, but whether acknowledged constraints are reliably bound to the immediately following executable action. The evidence separates instruction comprehension, textual acknowledgement, executable state, and actual tool/action behavior. It also distinguishes observed facts from engineering interpretations and from internal causes that remain unverified without server-side telemetry.

The evidence package includes a controlled repeated-run series, source-provenance analysis, correction-recovery observations, multimodal/image-generation failures, and a later supplement documenting a sharp deterioration in recovery reliability on 5–6 Sep 2026. The report applies an explicit causal-discipline rule, the “Applause Principle”: temporal sequence alone is not sufficient evidence of causation.

Primary finding

GPT-5.6 Sol can understand and verbalize active constraints, but those constraints are not always reliably converted into effective pre-action gates or bound to the next executable action. Repeated textual correction does not guarantee reliable correction-to-action recovery.

Evidence standard

  • Observed fact: user instruction, assistant statement, visible tool action, file, commit, or output.
  • Localized action: attribution only where the relevant action is directly evidenced.
  • Internal cause: remains UNVERIFIED without telemetry sufficient to identify the responsible subsystem.
